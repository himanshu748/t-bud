# T-Bud Landing Implementation Inventory

## Accepted direction

- Product truth: Two independent agents can coordinate a valuable booking without removing human authority.
- Audience: Buildathon judges, AI builders and adventure merchants.
- Desired feeling: Capable, transparent and ready for real commerce.
- Primary action: Run the live booking demonstration.
- Visual concept: Trail Instrument, a protocol route that visibly stops at human approval.
- Archetype: Technical instrument with an editorial field-guide influence.
- Silhouette: Quiet header, asymmetric promise and live handshake, open evidence runway, value correction, failure recovery, dark architecture band and decisive close.
- Type: Condensed system display, neutral system body and tabular monospace protocol labels.
- Material: True white, graphite rules, protocol blue and alpine orange. Square geometry, almost no shadow and no gradients.
- Media: Code-native route lines, contour paths, status signals and real product UI. No raster or generated imagery.
- Signature moment: A blue protocol pulse moves from buyer to merchant and stops at the orange human gate.
- Avoid: chatbot-only layout, floating gradient cards and generic travel marketplace tiles.

## Above-the-fold copy lock

- Brand: `T-Bud`
- Navigation: `Protocol`, `Decision path`, `Architecture`
- Header control: `Human control: on`
- Heading: `Make every adventure bookable by an agent, without losing human control.`
- Support: `An A2A merchant adapter for Manali trek bookings. Agents can discover, compare and prepare checkout. People approve every hold and payment.`
- Primary CTA: `Run the live demo`
- Secondary CTA: `Inspect the Agent Card`
- Preview labels: `Buyer agent`, `A2A / message.send`, `Merchant agent`, `Awaiting human approval`
- Buyer request: `2-day Manali trek · 4 friends · under ₹20,000`
- Merchant evidence: `₹19,600 · pickup + upgraded meals`

## Section sequence

1. Hero handshake: demonstrate the exact agent exchange and human stop.
2. Protocol runway: A2A discovery, WebMCP parity, deterministic policy, approval gates and Razorpay test checkout.
3. Decision path: ₹16,000 base, ₹20,800 rejected, ₹19,600 approved.
4. Recovery route: budget conflict and last-seat conflict with renewed approval.
5. Cloudflare architecture: Workers, Workers AI, D1 and Durable Objects with concrete ownership.
6. Closing action: return to the live demo and Agent Card.

## Component and state rules

- Buttons: solid orange primary, bordered graphite secondary, 46px minimum height, visible focus ring and pressed offset.
- Status: semantic dot plus text, never color alone.
- Panels: open instrument regions separated by one-pixel rules, not floating cards.
- Icons: custom inline SVG only for route arrows and status marks, 1.5px square-ended strokes.
- Motion: one protocol pulse uses transform and opacity. Reduced motion leaves the pulse at the approval gate.
- Mobile: hero becomes request, protocol route, merchant evidence and CTA sequence. Navigation anchors hide, human-control status remains and route lines become vertical.
- Empty, loading and error states live in the demo, not as decorative landing-page controls.
